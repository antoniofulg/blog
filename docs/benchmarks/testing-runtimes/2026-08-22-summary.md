# Testing runtime migration — evidence pack

**Date:** 2026-08-22  
**Machine:** Apple M3 Pro, 11 cores, 18 GB RAM  
**Versions:** Node 24.19.0, Bun 1.4.0, Vitest 4.1.5, Playwright 1.60.0  
**Scope:** local measurements from the `feat/bun-native-test-runner` branch

> **Historical / superseded (2026-08-24):** This evidence pack preserves the
> migration measurements and raw-report links. The current decision is Bun 1.4
> + Vitest permanently; Bun Test is retired after two local full-suite signals
> were roughly twice as slow (60.96 vs 119.71 s and 59.56 vs 127.88 s).
> Inventory/skip differences and shared-runner conditions made both
> uncontrolled rather than valid performance benchmarks; memory evidence was
> inconclusive, and the evidence did not justify maintaining the candidate. The
> shadow/cutover guidance retained below is historical only;
> no ten-run gate or Bun Test workflow is operational.

This page is the source index for the historical engineering post. It separates
repeatable findings from directional observations and invalid comparisons. Raw
reports remain linked so published claims can be traced back to evidence.

## Stack decision

| Layer | Canonical path | Comparison / rollback path | Status |
| --- | --- | --- | --- |
| Dependency install | Bun 1.4 | npm on Node 24 | Bun retained |
| Unit, component, integration | Bun 1.4 + Vitest | Node 24 + Vitest (reference/rollback) | Bun + Vitest permanent; Bun Test retired |
| E2E | Bun 1.4 + Playwright | Node 24 + Playwright | Bun retained |
| WebView smoke | None | Archived reports only | Experiment retired |

The blocking `test` command uses Bun 1.4 + Vitest permanently. Node 24 + Vitest
remains the explicit comparison and rollback route. Bun Test's exact static
parity and historical timing evidence are retained, but its runner and shadow
workflow are retired. Playwright remains the E2E framework, with an explicit
Node fallback.

The local low-memory profile is `test:local` with one Vitest worker. The latest
worker report's mathematical RSS winner was two workers (1685.6 MiB versus
1687.6 MiB, only 0.12% lower), but a fresh two-worker run failed two
`bench-runtime` tests due to a port/PID 843 race. Serialization is therefore
the operational choice for reliability; the medians are effectively tied.
See the [raw worker report](../vitest-workers/workers-2026-08-23T07-55-28-315Z.md).

## Findings safe to quote with scope

### Dependency installation

The first run warmed caches and was excluded. The two steady-state runs compared
`npm ci` with `bun install --frozen-lockfile` after deleting `node_modules`.

| Metric | npm / Node 24 | Bun 1.4 | Observed delta |
| --- | ---: | ---: | ---: |
| Time | ~8.7 s | ~1.9 s | Bun 4.6× faster |
| Peak RSS | ~1,095 MB | ~57 MB | Bun used 19× less memory |

This is the clearest measured gain. It is a result from one development machine,
not a general performance guarantee. Source:
[`node-vs-bun/README.md`](../node-vs-bun/README.md).

### Same Vitest suite on Node and Bun

Three interleaved rounds executed the same 124 files and 2,283 tests after the
React dependency-inlining issue was fixed.

| Metric | Node 24 + Vitest | Bun 1.4 + Vitest | Interpretation |
| --- | ---: | ---: | --- |
| Median time | 63.7 s | 62.2 s | 2.4% lower; overlapping spread, effectively tied |
| Median peak RSS | 3,379 MB | 2,927 MB | 452 MB lower; 13.4% observed median delta across three samples |

The data supports runtime compatibility and lower memory, not a meaningful
execution-time win. Lower memory is the deciding metric because the development
workflow commonly runs several worktrees concurrently. Source:
[`node-vs-bun/README.md`](../node-vs-bun/README.md).

### WebView experiment

Both arms used Bun 1.4, the same Chromium executable, server, database, viewport,
five public smoke scenarios, and matching DOM assertions.

| Primary measurement | Bun + Playwright | Bun.WebView | WebView delta |
| --- | ---: | ---: | ---: |
| Cold median, 5 measured runs | 1.820 s | 3.109 s | 70.84% slower |
| Cold browser RSS | 729.6 MiB | 907.7 MiB | 24.41% higher |
| Warm-session median, 10 measured passes | 0.514 s | 1.476 s | 187.38% slower |
| Warm-session browser RSS | 800.7 MiB | 915.1 MiB | 14.30% higher |
| Whole warm-session process median | 3.984 s | 10.313 s | 158.88% slower; 2.589× |

Warm-up-inclusive views were retained as secondary evidence:

| Warm-up-inclusive measurement | Bun + Playwright | Bun.WebView | WebView delta |
| --- | ---: | ---: | ---: |
| Cold median, 6 samples | 2.073 s | 3.158 s | 52.31% slower |
| Cold total | 13.126 s | 18.730 s | 42.69% higher |
| Warm-pass median, 12 samples | 0.525 s | 1.480 s | 181.69% slower |
| Warm-pass total | 6.259 s | 20.125 s | 221.55% higher |

The experiment supports retiring WebView for this project. It does not compare
equivalent framework capabilities: WebView covered five public scenarios, while
Playwright's full suite has 49 tests plus fixtures, auth state, locators, traces,
retries, reporters, permissions, and request inspection. Sources:
[`cold report`](../e2e-webview/comparison-cold-2026-08-22T20-24-33-426Z.md),
[`warm-session report`](../e2e-webview/comparison-warm-session-2026-08-22T20-24-33-426Z.md),
and the archived [`methodology`](../e2e-webview/README.md).

## Historical compatibility evidence; do not use as a speed claim

The independently verified migration reached exact static parity. This section
is historical evidence for the retired candidate:

- 138 files in each tree;
- 2,289 static test declarations in each tree;
- 3,761 static assertions in each tree;
- 34/34 specification acceptance criteria verified;
- 3/3 adversarial mutations detected.

One sequential A/B/C validation produced:

| Arm | Runtime + runner | Files | Outcomes | Time |
| --- | --- | ---: | --- | ---: |
| A | Node 24 + Vitest | 138 | 2,343 pass, 52 skip | 66.14 s |
| B | Bun 1.4 + Vitest | 137 | 2,335 pass, 52 skip | 60.96 s |
| C | Bun 1.4 + Bun Test | 138 | 2,343 pass, 57 skip | 119.71 s |

The raw B delta is 7.83% faster than A, but B discovered one fewer file and
passed eight fewer tests. A and C reported five different skip outcomes. The
benchmark correctly invalidated both performance conclusions. These numbers
prove the comparison harness catches unequal outcomes; they do not prove a
winner. Source: [`validation.md`](../../../.specs/features/bun-native-test-runner/validation.md).

## Directional observations requiring a persisted rerun

A local stable-subset comparison ran the same 44 Playwright tests five times per
runtime, excluding five unstable locale-switcher tests:

| Runtime | Runs | Median | Mean | Median RSS |
| --- | --- | ---: | ---: | ---: |
| Node 24 + Playwright | 13.21, 12.08, 11.90, 12.51, 11.51 s | 12.08 s | 12.242 s | 1,101.4 MiB |
| Bun 1.4 + Playwright | 10.56, 10.33, 10.66, 10.63, 10.21 s | 10.56 s | 10.478 s | 1,135.9 MiB |

The raw deltas favor Bun by 12.58% on median time and 14.4% on mean time, with
3.13% higher median RSS. Treat this as directional only: the raw logs were
temporary and the comparison excluded five tests. A full 49-test attempt was
also invalid because both arms passed only two of five repetitions, failing the
same locale-switcher cases. No Node-versus-Bun Playwright performance claim
should be published until this benchmark is rerun and committed.

Compatibility gates later passed all 49 tests through Bun. The Node fallback
also passed 49/49 after one full retry following a PGLite lock timeout. These are
green gates, not controlled performance samples.

## Historical fresh pre-merge verification

After retiring the executable WebView harness and adding the hydration
regression, both unit-test trees remained in parity. Node 24 + Vitest passed
2,346 tests with 52 skips in 59.56 seconds; Bun Test passed the same 2,346 tests
with 57 skips in 127.88 seconds. Lint had zero
errors and 17 existing warnings; typecheck, test-annotation lint, build, and
parity passed.

The first two full Bun + Playwright runs exposed an existing hydration race in
the locale switcher: the test forced a click on SSR markup before React attached
the handler. Node + Playwright passed 49/49 in 14.2 seconds because its timing
did not expose the same window. The product fix keeps language controls disabled
until hydration and the E2E now uses a normal actionability-checked click.

After the fix, the previously failing ordered subset passed, followed by three
consecutive full Bun + Playwright runs: 49/49 in 13.2, 12.4, and 13.8 seconds.
Each run left no E2E server or Nitro child process behind. The server harness now
awaits child termination and performs idempotent PGLite/state-file cleanup.
These are regression gates, not a new Node-versus-Bun performance benchmark.

## What not to claim

- Do not claim Bun Test is faster than Vitest from the current A/C run.
- Do not claim the 7.83% Bun + Vitest raw delta as a confirmed gain.
- Do not compare WebView's five scenarios with Playwright's full 49-test suite.
- Do not present the Playwright runtime subset as a reproducible benchmark until
  its raw report is persisted.
- Do not generalize single-machine results into universal Bun performance.

### Current operational choice

The latest worker matrix ran five measured samples plus one warm-up for each
profile. Timing comparison is invalid because ambient load exceeded the bound
in multiple samples. Memory comparison is valid: profile `2` measured 1685.6
MiB median peak RSS versus 1687.6 MiB for profile `1`, a 2.0 MiB (0.12%)

port/PID 843 race. `test:local` therefore stays serialized at profile `1` for

and its [raw JSON](../vitest-workers/workers-2026-08-23T07-55-28-315Z.json).

### Current Playwright evidence

The persisted full Chromium benchmark uses the same Bun application server,
one worker, zero retries, and five measured samples per runtime. Every sample
passed 49/49 with zero skips, unexpected, or flaky outcomes. Bun's median was
11.356 s versus Node's 12.998 s (-12.63%), and median peak RSS was 361.5 MiB
versus 796.6 MiB (-54.62%). This is a scoped, persisted benchmark result, not
a universal runtime claim. See the [raw JSON](../e2e-runtimes/runtimes-2026-08-23T08-20-02-241Z.json)
and [report](../e2e-runtimes/runtimes-2026-08-23T08-20-02-241Z.md).

The cross-browser gate also passed 49/49 in each configured project under Bun,
